### Special case: MX1 (1 of 21)

MX1 is now `Not_DE_outside_noise` and is **not** eQTL-evaluated.

- Raw (uncorrected) analysis: log2FC 1.153, padj 1.06e-18 - strongly up.
- Ploidy-corrected: log2FC 0.819 (dev/SD = **2.04**, the third largest
  deviation on chr21), but DESeq2 returns **pvalue = NA and padj = NA**
  while still reporting `stat` = 5.63. It is one of only 3 chr21 genes and
  217 genes genome-wide with a nulled p-value, the signature of DESeq2's
  Cook's-distance outlier filtering.
- Under the old stale table MX1 had norm_padj = 1.18e-04, which is why the
  abstract lists it as a positive control.

**This needs a decision.** MX1 has a large, consistent deviation but no
usable p-value, so the current filter (`!is.na(norm_padj)` in script 02)
silently excludes it. Options: investigate the outlier samples driving the
Cook's flag, re-run `results()` with `cooksCutoff = FALSE`, or report MX1
separately as an excluded-but-notable gene. Do not simply reinstate it
without resolving why the p-value is missing.

### New gene not in the abstract: ERG

## The bug that caused this

Scripts 02 and 04 read `results/tables/deseq2_chr21_combined.csv`, dated
**2025-11-11**. No script writes that file any more: commit `4e116fb`
("applied the correct library size normalization to account for ploidy in
DESeq2") changed script 01 to write `deseq2_chr21_genes_both_analyses.csv`
instead, regenerated 2026-05-15.

Consequences before the fix:

1. Lane assignment, the Sankey, and all headline numbers were computed from
   **pre-ploidy-fix** chr21 DESeq2 results.
2. Those were compared against a cohort-noise SD computed from the
   **post-fix** genome-wide table - two incompatible DESeq2 runs mixed in
   one filter.
3. `raw_log2FC` was unaffected (identical across both tables); only the
   ploidy-corrected values moved, by a mean of 0.101 log2 units.
4. The stale file is gitignored and never regenerated, so a fresh clone
   would have failed at script 02 with a missing-file error.

Fixed by repointing both scripts to `deseq2_chr21_genes_both_analyses.csv`.
Evidence the new run is the correct one: chr21's median ploidy-corrected
log2FC moves from -0.130 to **-0.027**, i.e. much closer to the zero the
ploidy correction is supposed to produce.
